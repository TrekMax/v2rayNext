# 订阅授权与有效期设计

状态：推荐方案已实现，本地验证完成；目标服务器 HTTPS、systemd/Docker 实机及客户端验收待部署后执行。

## 目标与范围

为 Base64 和 Clash 订阅增加随机授权码、服务端有效期校验和单条授权撤销。不兼容旧的匿名订阅链接，这是用户明确的要求。

完整订阅链接是访问凭证：持有完整链接的人在有效期内仍然可以下载。此次功能控制订阅下载，不撤回已下载的节点配置，不限制代理连接时长，也不实现设备绑定、用户账号或支付系统。

## 升级前的实现

- `src/cmd.sh` 将 `sub / subscription` 命令交给 `src/config.sh` 的 `sub()`。
- `sub()` 和 `_sub_write_clash()` 分别生成 `/etc/v2ray/sub.txt`、`/etc/v2ray/sub-clash.yaml`。
- 仓库自身没有订阅 HTTP 服务。README 提供 Nginx `alias` 静态下载示例，无法执行逐次授权或过期检查。
- Linux 安装由 systemd 管理服务；Docker 使用自带的 `systemctl` 包装脚本。

## 方案比较

1. **独立订阅服务（推荐）**：每个链接拥有独立随机凭证、过期时间和撤销状态。Nginx、Caddy 均可反向代理，支持单条撤销。代价是增加一个仅监听本机的服务和 Python 3 依赖。
2. **固定授权码**：改动较小，但泄漏后一直有效，轮换共享授权码会影响所有客户端。
3. **Nginx 签名有效期**：无需独立应用服务，但依赖 `ngx_http_secure_link_module`，并且单条链接撤销需要额外状态管理，不直接适用于当前 Caddy 部署。

Nginx 官方文档说明该模块需要构建时启用：<https://nginx.org/en/docs/http/ngx_http_secure_link_module.html>。

以下设计对应方案 1。

## 命令接口

```bash
# 初始化订阅服务；地址必须是 HTTPS origin，不含路径、查询或认证信息
v2ray sub setup https://sub.example.com

# 生成对应格式的订阅内容，并创建独立授权；默认有效期 7 天
v2ray sub
v2ray sub clash --ttl 30d --name phone
v2ray sub base64 --ttl 2h --name laptop

# 更新文件内容，不创建授权、不改变现有授权有效期
v2ray sub refresh base64
v2ray sub refresh clash

# 列出授权 ID、名称、格式、创建/到期时间和状态，不显示凭证明文
v2ray sub list

# 单条撤销，后续请求立即失效；不影响其他授权
v2ray sub revoke <id>

# 订阅服务生命周期
v2ray sub start
v2ray sub stop
v2ray sub restart
v2ray sub status
```

`--ttl` 支持正整数加 `s/m/h/d`，默认 `7d`，拒绝零、负数、格式错误和超过 365 天的时长。每次发放时输出授权 ID、到期时间和完整 URL。链接仅在创建时输出，遗失后重新创建并撤销原授权。

没有完成 setup 时，生成命令提示先配置服务，不回退到匿名文件输出。订阅内容保持现有协议转换规则；节点配置变化后执行 refresh 或重新生成对应格式。

## 数据与访问流程

1. 将订阅内容写入 `/etc/v2ray/subscription/` 私有目录中的临时文件，生成成功后原子替换正式文件。目录权限 `0700`，文件权限 `0600`。
2. 使用密码学安全随机数生成 256 位授权码；SQLite 只保存授权码的 SHA-256 摘要、随机授权 ID、名称、格式、创建时间、到期时间和撤销状态。
3. 输出 `https://sub.example.com/sub?token=...` 或 `/sub-clash?token=...`。授权绑定格式，不能通过替换路径获取另一种格式。
4. 客户端经 HTTPS 反向代理访问监听 `127.0.0.1:8787` 的订阅服务。
5. 服务在每次 GET/HEAD 请求中验证参数、凭证、授权格式、撤销状态和服务器当前时间。到期条件为 `now >= expires_at`，无须定时任务或重启。
6. 校验通过后只读取预定义订阅文件，不接受用户指定的文件路径、不调用 Shell、不提供目录列表。

管理操作仅通过本机 CLI 提供，不开放 HTTP 管理接口。数据库事务保证并发创建与撤销；服务重启后授权状态保持。订阅文件和配置同样持久化。

缺失、错误、重复或不匹配的凭证返回 403；过期和撤销同样返回 403，不暴露具体授权状态。未知路由返回 404；合法授权对应内容缺失或存储异常时返回服务不可用，不返回节点内容。成功及错误响应均设置 `Cache-Control: no-store`。服务日志不记录完整请求 URL、查询串或凭证。

## 部署与旧入口

- setup 检查依赖，创建配置及独立 systemd 服务；Docker 安装 Python 3，并补充订阅服务管理与启动恢复。
- Docker Compose 增加订阅状态卷，重建容器后保留授权和过期时间。
- 服务仅监听本机，HTTPS 与公网连接由 Nginx/Caddy 负责；文档提供两者的明确路由配置及关闭订阅访问日志/缓存的示例。
- 初始化成功后移除两个旧的生成文件，之后不再写入旧路径。
- 外部 Nginx/Caddy 配置不在仓库控制下，不猜测或覆盖用户现有虚拟主机；部署步骤明确要求删除旧 `alias/file_server` 入口及已复制到 Web 根目录的订阅文件，并验证旧地址不再返回内容。
- 卸载停止并禁用订阅服务；脚本升级后重启已启用的订阅服务，使新代码生效。正常更新不覆盖授权数据库。

## 验证与验收

- 真实 HTTP 请求验证两种格式的合法下载、HEAD 和响应类型。
- 缺失/错误/重复凭证、未知路径、跨格式授权、路径穿越均不能取得订阅内容。
- 覆盖精确到期边界、单条撤销且其他授权可用、重启后的授权持久化。
- 覆盖非法 TTL、名称参数传递、输出不泄漏到日志、文件权限及状态损坏时拒绝访问。
- 覆盖生成失败保留上一份内容、不发放新授权，及更新内容不改变已有授权。
- 验证旧文件不再生成，旧入口迁移步骤与新反向代理配置一致。
- Bash 语法、针对性 Shell 检查、Python 自动化测试、`git diff --check`；具备可用 Docker 环境时运行 Linux 集成验证。
- 本地测试结果与远程 HTTPS、实际客户端导入、服务器部署验收分别报告。
